# ADR 0003：多态联合的结构树表示——分支列表为基础，判别式索引为派生优化

日期：2026-08-19
状态：已接受（Phase 0b 求值器设计前置决策）

## 背景

VFSL v1 的物化规则（`docs/vfsl/v1-spec.md`「默认物化规则」）规定：全容器形联合（如 fixture 的 `AssetEntity = { kind: "image"; … } | { kind: "video"; … }`）在同步物化上下文按**命中成员的形状**物化。而结构树是编译期从 schema 文本派生的静态蓝图——「命中哪个成员」是运行时数据事实，编译时不可知。**静态的单形状蓝图如何表达「一个位置、N 种形状之一」**，是求值器（IR → 结构树）必须先冻结的表示决策。

该表示是三个下游消费者的公共地基：`validateSnapshot`（结构 + 值校验）、路径下钻守卫、AI namespace card。节点形状一旦冻结即构成契约。

## 决策

**方案 A（分支列表）为唯一基础表示；方案 B（判别式索引）为纯派生优化，不进入契约。**

1. **基础表示（A）**：联合位结构节点为
   `{ kind: 'union'; members: StructureNode[] }`。运行时按序尝试，**匹配语义冻结为「至少一个成员接受即接受」**（any-of，非 exactly-one——重叠成员不构成错误）；
2. **判别式检测（B，派生）**：求值器在构造联合节点时检测「存在一个字段，其字面量在全体成员中两两互异」。命中则附 **非契约缓存** `discriminator: { field: string; map: Map<literal, memberIndex> }`，运行时 O(1) 跳转；未命中退化为逐个尝试，行为与 A 完全一致；
3. **no-match 诊断形态**：报**失败原因最少的成员**（而非罗列全部分支），消息标注「联合成员 1/2：缺 duration 字段」式相对定位；
4. **路径存在性语义**：字段在**任一**成员中出现即视为该路径存在（`replace /assets/x/duration` 在 image 实例上路径合法，值校验阶段再行拒绝）。

## 理由

- **通用性是硬要求**：v1 方言不要求联合带判别式（`{ host: string; port: number } | { url: string }` 合法），B 无法覆盖全部合法输入；强制要求判别式等于收紧方言，违反「v1 冻结、只增不改」；
- **B 是缓存不是契约**：索引存在与否不得改变可观测行为（含错误输出）；这让 B 可以独立演进、按需禁用，不产生第二真相；
- **排除方案 C（字段并集超集）**：合并丢失互斥信息，会接受不属于任何成员的数据（如 `{ kind: "image", duration: 30 }`），值校验失效——语义错误，不是取舍问题；
- **问题域已收窄**：shapes.ts 的三分类（`clsOf`）在解析层保证全标量联合退化为叶子值（不进结构树）、混合联合被 E309 拒绝——结构树中的联合节点只剩「全容器联合」一种情形，且判定基础设施可直接复用。

## 后果

- 正面：方言零改动；下游消费者只需实现「按序尝试 + any-of 语义」一种心智模型；判别式场景（fixture 的 AssetEntity）获得 O(1) 与精准报错；
- 负面：无判别式联合的校验为 O(成员数)；重叠成员的「哪个成员匹配了」不可观测（any-of 语义下无意义）；
- 边界义务：求值器实现须保证 `discriminator` 缓存的缺失/存在不改变任何测试可断言的行为（SA6 红灯须覆盖：同一无判别联合在「逐个尝试」路径下的接受与拒绝）。
