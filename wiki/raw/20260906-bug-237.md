## Symptoms

普通非空路径 mutation（改一个叶子字段）在 live Y.Doc 上只提交 30–33 字节的 owned update，但其**准备与验证成本与整个 ROOT 规模线性相关**：

1. **每笔叶子写毫秒级到秒级**：ROOT 含 64,000 个无关 `YArray` 条目时，单笔 `set ['target','value']` 稳态 ~3.4–3.6 s；8,000 条目时 ~0.9–1.0 s；1,000 条目时 ~0.09 s。成本全部花在与 mutation 无关的分支上。
2. **连续五笔叶子写被逐笔放大**（Owner benchmark 场景）：8k 无关条目下 5 笔 `mutateData` 共 4.72 s；64k 条目下 5 笔共 18.5 s——单 namespace 唯一 FIFO write sequencer 槽被逐笔占满（`write.ts:143` 的 `applyValidatedMutation` 在槽内同步执行，head-of-line blocking 叠加）。
3. **校验失败语义耦合全 ROOT**：mutation 路径完全合法时，若**无关分支**存在非法数据（如 replication-unvalidated 状态），普通写也会被拒（复现见 R2）——这是 ADR-0010 L107 现文登记的拒绝通道，phase-1 后按 Owner 授权收窄为「路径/边界内非法数据仍响亮拒绝，无关分支不再被普通写发现」。
4. **内存抖动**：16k 无关条目下 5 笔叶子写期间 heap 增量 ~114 MB（指示性，未强制 GC）——完整快照 + JSON 深拷贝 + scratch doc 整 ROOT 重物化。

### R2 — 无关分支非法数据 ⇒ 普通写被拒（现行语义基线，Stage B）

经 live carrier 直接把无关叶子 `library[0].qty`（number）改成 `'corrupt-not-a-number'`（绕过校验——replication-unvalidated / 损坏存量的形状）后：

```json
{"mutationPath":["target","value"],

```

即：**mutation 路径合法，拒绝由无关分支的旧 ROOT 全量校验触发**；失败零写入（state 字节不变、0 个 update 事件）。对照组（干净 doc + 非法新值）在 `['target','value']` 拒绝，同样零写入。phase-1 后 R2 主用例的期望将反转为「成功 + 已声明的前置假设语义」（Owner 评论 1），SA6 必须把该反转锚定为**声明语义而非疏漏**。

{"perCallMs":[921.8,1001.1,946.7,989.7,862.6],"totalMs":4721.9,

## Investigation

读取（全部逐个读过）：`packages/doc-runtime/src/mutation.ts`（437 行全文）、`install-verify.ts`（329 行全文）、`extract.ts`（walk/extractYjsSnapshot）、`read.ts`（readLogicalValueAtPath 头部）、`index.ts`（公共面）、`packages/vfsl/src/validate.ts`（validateLogicalSnapshot/validateSubtree）、`validate-patch.ts`（686 行核心段 + 四个公共接缝）、`packages/namespace-runtime/src/write.ts`（S1–S7 槽序）、`runtime.ts`（seam 构造）、两包 AGENTS.md、CONTEXT.md 词条、ADR-0007/0008/0010 相关条款、issue #230 回归测试。

★ 即缺陷点：**单笔普通写付出 ~7 遍完整 ROOT 遍历 + 2 次整树快照物化 + 1 个整 ROOT scratch doc**，其中与 mutation 相关的只有路径导航与边界值。

关键旁证：

- `grep -rn 'validate-patch|validatePatch|validateInsertIntoArray|validateDeleteFromArray' packages/doc-runtime/src packages/namespace-runtime/src` → **零命中**：vfsl 已有的路径级校验接缝（`validate-patch.ts:611-680`：guardWalk 结构守卫 O(路径长×结构树节点) + rebuildOp 最近结构边界重建 + `finish`→`validateSubtree` 整体过子 schema）从未被写路径消费；`mutation.ts:8` 只 import `validateLogicalSnapshot`。
- 词汇缺口：`validateInsertIntoArray` 单元素 `value`、`validateDeleteFromArray` 单 `index`（隐含 count=1），而 mutation 词表是 `array-insert values[]` 批量与 `array-delete count` 批量——逐元素独立校验会漏掉「中间态/终态合法性不同」的整批语义（issue 明令不得逐元素）。
- `readLogicalValueAtPath`（`read.ts:53`，ADR-0008 读取面）已存在**路径局部**的 carrier 投影读取，但 schema-independent——不含 union 边界解析/结构树仲裁；`mutation.ts` 自有 `navigateLive`（含 `resolveNode` union 匹配）沿路径导航 live carrier，说明「沿路径只触达必要节点」的机制在两处已有先例，缺的是把它接到校验/提取/验证三段。
- git 考古：`mutation.ts` 全量管线自 `5db6f83`（2026-08-25，Phase 3 #85）落地即如此；`a3e9266`（2026-09-05，#230/#236）完成「提交阶段最小化」（保留 carrier identity、最小 edit），`1c8b907` 同日落档 ADR——**校验/提取/验证三段从未局部化**，即 ADR-0007 L59 后果句「validated mutation 为正确性继续执行完整 ROOT 提取与逻辑校验……继续优化完整校验成本时必须保留行为等价测试」预告的下一步。

## Root Cause

`applyValidatedMutation`（ADR-0007 规范行为，非实现走样）把「正确性」实现为**对完整 ROOT 的三重全量处理**，而非沿 mutation 路径的局部不变量维持：

| # | 缺陷点（文件:行） | 现行为 | 应有（issue 目标） |
|---|---|---|---|
| 1 | `mutation.ts:72` | 每笔写完整 `extractYjsSnapshot`（整树拷贝） | 沿导航路径提取最近必要语义边界的 logical value（路径级 carrier 检查） |
| 2 | `mutation.ts:74` | 每笔写完整校验**旧** ROOT（R2 的无关分支拒绝点） | 删除热路径旧 ROOT 全量校验；phase-1 前置假设「mutation 前 committed ROOT 已符合 active schema（logical values + carrier topology）」由 create/replaceSchema 合法性建立点归纳维持 |
| 3 | `mutation.ts:77` | `cloneJson` 整树深拷贝模拟 mutation | 在 detached 局部边界值上模拟（O(boundary)） |
| 4 | `mutation.ts:81` | 完整校验 proposed ROOT | 复用/扩展 `validate-patch.ts` 家族在最近结构边界重建整值后过子 schema（判别联合/Record/optional 语义一致）；schema 需要更大上下文时安全退化到更高边界直至 ROOT |
| 5 | `mutation.ts:61`+`install-verify.ts:122-169` | `verifySnapshotIntact` 对称重物化整 ROOT 进 scratch doc + 双侧整树提取 + 全树比较 | 边界级提交后验证（受影响 carrier/逻辑边界与预期一致）；internal invariant 检查不再无条件回到 O(ROOT)；fatal 分类（committed:true、E201 家族、不回滚不补偿）不削弱 |
| 6 | `write.ts:143`（槽内同步执行上述全量） | 全量成本逐笔占用唯一 FIFO 槽 | 槽序 S1–S7、公共 interface、结果联合、fatal 契约全部不变；仅槽内「领域校验」执行范围收窄 |
| 7 | `vfsl/validate-patch.ts:611-680` | 路径级接缝存在但无批量数组形态，且写路径零消费 | 扩展批量 `values[]`/`count` 整体重建校验；doc-runtime 消费之（vfsl 保持无 Yjs 依赖——carrier 检查留在 doc-runtime，与 ADR-0007 分层一致） |

**语义基线（今天 vs phase-1 后，SA6 锚定对象）**：

- 今天：R2——无关分支非法数据 ⇒ 普通写被拒（ADR-0010 L107 登记的 replication-unvalidated 后备通道）。phase-1 后（Owner 授权 + E3）：**mutation 触达路径/边界内的非法数据仍响亮拒绝；无关分支不再被普通写发现**——必须在测试前置条件与内部契约里显式声明该假设，并证明无关 ROOT 分支不被访问/复制/校验。
- 不变项（不得回归）：校验失败零 Y.Doc 写入、零 dirty notification、失败判定先于任何 live 写（禁止 write 后 undo）；单 guarded transaction；最小 edit + 保留不相关 carrier identity；每笔成功恰 1 次 dirty notification、1 个 owned update；`set([])` 全量清空重装、create/`replaceSchema` 全量校验（合法性建立点）不动；fatal 分类与 post-write invariant 保障不削弱。

## SA6 红灯锚定清单（供 SA6 固化、SA1 设计纳入）

1. **行为等价（硬验收，ADR-0007 L59 明文前置）**：对相同合法 base/mutation，增量判定 ≡ 「构造完整 proposed ROOT 后 `validateLogicalSnapshot` 全量校验」（oracle 即现行 L74/L81，天然在场）。
2. **热路径去全量**：ordinary 非空路径 mutation 期间完整 ROOT extract/clone/validate 调用数为 0（内部 instrumentation/计数 seam，不扩公共 API、不新增公共事件订阅——ADR-0008 status 观测面条款）；无关分支零访问/零复制/零校验。
3. **导航路径局部 carrier topology 校验**：document valid = carrier topology + logical value；不实例化不匹配 carrier。
4. **无关非法数据语义反转**：R2 主用例从「拒」变「成」，且作为**声明语义**锚定（前置假设显式写入测试/内部契约）。
5. **批量数组**：`array-insert values[]` / `array-delete count` 整体一次校验（不逐元素）；中间态非法终态合法等组合行为与全量校验一致。
6. **退化**：schema 语义要求更大上下文时安全退化到更高边界直至 ROOT（行为覆盖闭包）。
7. **提交后验证**：不再无条件完整 ROOT 再提取/校验；边界级偏离仍走 committed fatal（不回滚）。
8. **零写入/fatal/嵌套路径/carrier identity** 回归（现行测试族继续绿）。
9. **benchmark/instrumentation**：大 ROOT + 连续五笔叶子 mutation（fake clock 压缩 30s 周期），证明无关分支不访问/复制/校验，且 dirty notification 计数（=5）与 wire update 计数（=5，`docs/protocols/instance-replication-v1.md` 为唯一 wire 权威）保持；**不把 #238 replication latency 归因本 issue**。
10. **文档义务（E1–E4，随代码交付）**：ADR-0007 显式修订节（含热路径全量校验删除、新前置假设、边界级 proposed 校验、提交后局部验证、损坏条款收窄）+ ADR-0008 §ROOT write 同步 + ADR-0010 L107 后备句修订与 follow-up 显式登记（replication/损坏存量/不可信恢复的合法性重建、carrier 覆盖面审计）+ CONTEXT.md「逻辑快照校验」「复制未校验」词条修订。

## Fix direction（SA1 输入，非约束）

在 `applyValidatedMutation` 内部（公共面零变化）：沿 live carrier + derived structure 导航至目标（复用/收敛 `navigateLive`/`resolveNode` 的 union 仲裁与 `read.ts` 的路径局部读取纪律）→ 提取最近必要语义边界 logical value → detached 局部模拟 → 扩展 `validate-patch.ts` 批量接缝做边界级校验（vfsl 无 Yjs 依赖保持）→ detached 构造待安装 carrier → 单 guarded transaction 最小 edit → 边界级提交后一致性验证（保留 E201 committed fatal 族）。需要 ROOT 级语义时退化上限即现行全量管线。不建 committed-generation/document-baseline 状态机（Owner 评论 1 + 冲突报告对照 9）。
